# OpenCode 执行期间的新消息响应：需求与基线检查

## 目标与当前范围

用户在 2026-11-18 确认的目标：原任务尚在推进时，补充要求、临时提问、暂停和停止指令应能及时影响后续行为，不必等待整个任务结束。优先改进已经验收通过的 OpenCode 路线，保留模型、GPU 服务、现有会话与 airgap 部署方式。Codex 客户端仅作为后续备选，本次不接入。

本次只做第一步：增加隔离基线检查，定位消息等待发生在终端输入、原生会话后台还是工具/模型请求边界。不修改运行时配置、原生客户端、消息队列或执行工具；不实现此前暂缓的通用后台任务系统。

## 隔离检查怎么运行

在装有 Linux 原生客户端的 BCM、开发机或 CPU CI 中，从包含本脚本的源码根目录执行。以下沿用程序目录 /raid/local-ai；把客户端目录换成实际本机架构位置。只使用本机模拟模型和临时文件，不访问真实模型或 GPU；无需提交集群作业。

```bash
cd /raid/local-ai
PYTHONPATH=src python3 scripts/check-steering.py --client-dir /raid/local-ai/clients/amd64 --output /tmp/local-ai-steering-evidence
```

--client-dir 与 --output 必填。--output 必须不存在，避免覆盖既有证据；每次运行换一个目录。--mode 为 api、tui 或 both（默认），--hold-seconds 默认 5，必须大于 0 且不超过 60，--timeout 是每条路径的总期限，默认 90 秒且必须大于等待时长。这些数字是可调的测试窗口，不是产品响应保证或全局进度汇报频率。

两条路径均先通过原生 API 开始同一类无副作用的 Shell 等待命令。确认命令实际开始后，api 路径通过会话 API 发送补充消息，tui 路径附着真实 TUI 并通过伪终端输入文本与 Enter。模拟 API 返回固定工具调用及确认文本，以隔离模型决策差异；不会测试真实模型能否正确理解自然语言。

测试使用临时项目、会话配置、缓存与历史目录，不加载个人 OpenCode/Claude 规则；固定模拟命令只在临时项目写时间戳与一次执行标记。原生客户端仍可能需要其已准备好的 SDK/插件依赖，严格 airgap 时应先备齐；本脚本没有新增联网下载步骤，也不以本机模拟 API 代表已完成断外网验收。失败及结束时请求终止隔离会话并回收该次客户端进程。

## 证据与结果含义

新建证据目录权限 0700，report.json、api/tui-events.json 和后台日志为私有文件。事件包含相对同一单调时钟起点的秒数，不包含真实提示词、认证或用户任务数据。API/TUI 证据只来自本次模拟会话；后台日志可能包含临时路径。CPU CI 保留证据 artifact，成功测量与失败都保留已取得的部分结果。

| 事件或字段 | 含义 |
|---|---|
| tool_started / tool_finished | 模拟命令自身写出的开始与结束时刻 |
| follow_up_submitted | 测试端发起 API 提交或写入终端文本的时刻 |
| follow_up_persisted_observed | 轮询首次看到用户消息在原生会话中保存；这是观察时刻，不是精确接收时刻 |
| follow_up_in_model_request | 本机模拟 API 首次收到带该补充用户消息的主会话模型请求；标题等无工具请求不计 |
| ack_persisted_observed | 首次看到模拟确认文本保存为助手消息；不等于真实模型理解了要求 |
| delivery_phase | during_tool 表示命令结束前已进入模型请求；after_tool 表示之后才进入 |
| backend_visible_before_tool_end | 结束前是否已观察到消息保存，辅助区分接收与模型交付 |
| command_runs_once | 核对等待命令没有因新消息重复执行 |

退出 0、state=measured 只表示完整测得两种事件顺序之一，不保证响应目标达成。immediate_delivery_in_all_cases 仅在所有测量路径都为 during_tool 时为 true，也只针对该测试窗口。缺少必要事件、工具被意外终止、消息丢失、命令重复、超时或客户端错误时退出非零并保留失败报告，不能从失败推导出“产品只是不支持即时响应”。

## 首次实测基线：OpenCode 1.19.5

2026-11-18 在 Linux AMD64 CPU CI、提交 6020cdd 上测量，模拟 Shell 持续 5 秒。[完整 CI 与 steering-probe 证据](https://github.com/junli-nv/local-ai/actions/runs/44326930925)保留 report.json 和各路径事件。三个 Python 版本的回归与原生客户端契约全部通过；即时响应目标仍未达成。

| 路径 | 发送后首次观察到后台保存 | 发送后进入模型请求 | 相对命令结束 | 分类 |
|---|---|---|---|---|
| API | 约 0.070 秒 | 约 5.006 秒 | 结束后约 0.039 秒 | after_tool |
| 真实 TUI 输入＋Enter | 约 0.242 秒 | 约 5.023 秒 | 结束后约 0.051 秒 | after_tool |

两条路径均在命令结束前观察到用户消息保存，命令各执行一次，模拟确认随后保存，没有提交或模型服务错误。因此，这次场景支持“新消息已进入会话后台，但等阻塞 Shell 返回后才进入主会话模型请求”的判断，不能归因于消息未被界面接收或提示词没有要求及时响应。观察时刻受轮询影响，以上数字不是精确收件延迟、性能基准或跨版本保证；没有测试自然语言暂停/停止的实际效果。

首次脚本运行在创建工作区会话时沿用了过短的普通查询超时，尚未进入测量即失败；修正为使用本条路径剩余总期限后取得以上完整结果。失败运行不用于判断消息响应能力。

## 后续完善清单

- 根据当前版本与隔离候选版本的时序结果，先判断是否可复用原生引导能力，再决定是否需要局部执行工具适配。不直接替换已经通过验收的客户端。
- 区分模型正在生成、短工具执行、长 Shell 执行与排队模式；当前检查只覆盖长 Shell 中的一条补充要求，不代表其他模式。
- 验收补充条件影响后续操作、临时问题回答后续作、暂停后不启动新步骤，以及停止明确任务后核实进程结束。
- 区分暂停助手与取消运行中命令；普通补充要求不应隐式杀掉原任务。多个任务指向不明时需澄清。
- 后续变更继续验证会话恢复、不重复写入、权限边界、进程回收、无外网运行及原有客户端契约。
- 本页需求记录不是启动异步系统、迁移客户端或更改远端服务的授权。
